            About Shoalscan
            
    
            
      
            Why “Shoalscan”? A shoal is a stretch of shallow water hiding sand banks or rocks just under the surface. Ships run aground on shoals because, from above, the water looks open and safe. Lighthouses exist mainly to warn ships away from hazards like these.
            
      
            Security flaws behave the same way. Code can look fine at a glance while the danger sits just below. Shoalscan maps those hidden hazards. The baseline is a chart of the shoals you already know about, so a change is flagged only when it sails into new ones.

            The limits of static analysis
            
    
            No scanner finds every vulnerability. Pattern and taint analysis misses authorization and logic flaws, data flows across files, and concurrency bugs. A clean scan means only that these rules found nothing; it does not mean the code is safe. Shoalscan is one layer of defence alongside dependency audits, tests and code review.
            
    
            Fingerprints follow code as lines move, but an edit to the matched code or to the enclosing function's name makes a finding look new. Ages and times to fix on this dashboard count from the first recorded run that contained a finding, so for findings older than the history they are lower bounds.
